# 统一输出排版规范（按平台分区、统一字段）

所有交付的报告都按本规范排版，保证抖音、快手、百度三平台结果**结构一致、可横向对比**。

## 一、总原则

1. **平台顺序固定**：抖音 → 快手 → 百度好看视频，标题分别用 `## 抖音`、`## 快手`、`## 百度好看视频`。
2. 只做了单平台时，只保留该平台分节，但报告头部仍写明"本次平台：X"。
3. 某平台受阻（如快手未登录、无结果）也要保留该分节，写明状态：
   `> 未采集：快手网页版需登录，已暂停（等待扫码）` 或 `> 本关键词无结果`，不得静默缺失。
4. 平台内**表头字段统一**（见下），同一指标跨平台用同一列名（如"热度"列下抖音/快手是点赞、百度是播放量，并在表头注明）。
5. 每份报告开头放统一信息块：
   ```
   > 竞品/素材：<词或名> ｜ 本次平台：抖音/快手/百度（默认三平台）｜ 口径：抖音/快手按点赞、百度按播放量
   > 采集时间：<YYYY-MM-DD HH:MM> ｜ 数据为平台采集时点近似值，非官方热榜
   ```

## 二、模式1：爆款清单_<词>.md（脚本生成）

由 `scripts/make_hotlist.py` 直接产出，已经按平台分节。字段固定：

- 抖音/快手：`排名 | 作者 | 标题 | 点赞 | 评论 | 发布时间 | 链接 | 备注`
- 百度：`排名 | 作者 | 标题 | 播放量 | 发布时间 | 链接 | 备注`

## 三、模式1：爆款拆解_<词>.md

### 3.1 逐片拆解（每片一节，标题必须带平台前缀）

```
### [抖音] 01 <视频标题>（作者 · 点赞8.1w · 07-20）
- 链接：…
- 前3秒钩子：<画面/首句>（钩子类型：…）
- 结构节奏：0-3s … / 3-15s …（时间轴）
- 卖点话术：…（含数字/对比）
- 信任状：…
- 视觉包装：字幕样式/贴纸/运镜/BGM
- 结尾CTA：…
- 可复用爆点：…
```
快手、百度同结构；百度没有点赞时写播放量。

### 3.2 横向共性（跨平台汇总，按平台分三列或分点）

```
| 维度 | 抖音 | 快手 | 百度 |
|---|---|---|---|
| 高频开头钩子 | … | … | … |
| 常见时长 | … | … | … |
| 核心卖点/话术 | … | … | … |
| 视觉套路 | … | … | … |
| 结尾CTA | … | … | … |
```

## 四、模式1：爆款开头方案_<词>.md

每个开头标注借鉴来源平台；同一套开头尽量给"三平台通用版 + 平台差异化提示"。

```
## 开头 1：<钩子类型>（借鉴：抖音 <链接>、快手 <链接>）
- 前3秒画面（分镜）：…
- 前3秒字幕（大字）：…
- 口播文案：…
- 所需素材：…
- 平台适配：抖音…；快手…；百度…（如某平台对该话术更敏感，注明）
- 为什么有效：…（对应横向共性）
```

## 五、模式2：原创溯源报告_<id>.md

候选表按平台列出来源，置信度排序：

```
| 置信度 | 平台 | 账号(认证) | 链接 | 发布时间 | 匹配依据(画面/口播) | 是否最早 |
```
结论里写清：最可能原创（平台+账号+链接）；或"无逐帧一致原片/疑似共享素材库"。

## 六、模式3：素材预审报告_<素材名>.md

1. 命中明细先按**风险等级**分组（高/中/低），每条标 `来源(口播/画面/标题) | 时间 | 原文 | 风险点 | 类别 | 依据 | 修改建议`。
2. 平台适配结论按平台分三行：

```
| 平台 | 结论 | 主要驳回风险 |
|---|---|---|
| 抖音(巨量/千川) | 需修改后过 | 食品功效词、导流 |
| 快手(磁力) | 需修改后过 | 同上 |
| 百度(营销) | 需修改后过 | 功效词、落地页一致性 |
```

3. 结尾给"合规改写后的完整口播/字幕"和"需备资质清单"。

## 七、文件与成片命名

- 报告：`<类型>_<词或id>.md`，类型固定为：爆款清单 / 爆款拆解 / 爆款开头方案 / 原创溯源报告 / 素材预审报告。
- 下载原片：`downloads/<平台>_<作者>_<热度>_<视频id>.mp4`（平台取 douyin/kuaishou/baidu）。
- 修复成片：`修复成片_<id>_1080p.mp4`（2K 用 `_2K`）；原片：`原片_<平台>_<作者>_<id>.mp4`。
- 多平台打包时按 `downloads/<平台>/` 子目录归档。
